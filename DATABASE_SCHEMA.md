# GymPro SaaS - Database Schema Documentation

This document outlines the SQL data model used in the GymPro SaaS application. The database is built on **PostgreSQL** (via Supabase) and uses **Row Level Security (RLS)** to enforce multi-tenancy.

## 1. Core Architecture (Multi-Tenancy)

The system creates a "Silo" for each gym using the `tenant_id`. Every operational table (members, workouts, etc.) includes a `tenant_id` column. RLS policies ensure that a user logged in as a "Gym Owner" or "Staff" can ONLY see rows that match their `user.tenant_id`.

### `tenants`
Represents a Gym or Fitness Business.
- `id` (UUID): Primary Key.
- `name` (Text): Name of the gym (e.g., "Gold's Gym").
- `slug` (Text): Unique URL identifier.
- `owner_email` (Text): Email of the gym owner.
- `subscription_status` (Text): 'active', 'trial', 'expired', 'cancelled'.
- `subscription_expires_at` (Timestamp): When their SaaS plan ends.
- `features` (JSONB): List of enabled modules (e.g., `["members", "diet-plans"]`).
- `primary_color` / `secondary_color` (Text): Branding colors.

### `users_profile`
Extends the standard Supabase `auth.users` table with app-specific roles.
- `id` (UUID): Links to `auth.users`.
- `email` (Text): User's email.
- `role` (Text): 'super_admin', 'gym_owner', 'manager', 'trainer', 'member'.
- `tenant_id` (UUID): Links to `tenants`. **Crucial for RLS.**

## 2. SaaS Billing (Super Admin Context)

These tables manage the relationship between You (Software Provider) and the Gym Owners (Tenants).

### `saas_plans`
Available subscription packages for Gym Owners.
- `name` (Text): e.g., "Gold Plan".
- `price_inr` (Integer): Price in Rupees.
- `duration_days` (Integer): e.g., 365.
- `features` (JSONB): Features enabled by this plan.

### `saas_subscriptions`
Tracks the active plan for a tenant.
- `tenant_id` (FK): The gym having the subscription.
- `plan_id` (FK): The plan they are on.
- `start_date` / `end_date` (Timestamp).
- `status` (Text): 'active', 'cancelled'.

### `saas_invoices`
Invoices generated by the Platform for the Gym Owner.
- `invoice_number` (Text).
- `amount_inr` (Numeric).
- `status` (Text): 'paid', 'pending'.

---

## 3. Gym Operations (Tenant Context)

These tables store data specific to a single gym. All distinct by `tenant_id`.

### `members`
The gym's customers.
- `full_name`, `email`, `phone`.
- `status` (active/inactive).
- `join_date`.

### `memberships`
Plans the gym offers to its members (e.g., "3 Months Cardio").
- `name`, `price`, `duration_months`.

### `branches` & `services`
- Locations and Facilities offered by the gym.

---

## 4. Fitness Module

### `workouts`
Workout Templates created by Trainers/Owners.
- `name` (Text).
- `difficulty` (Beginner/Adv).
- `exercises` (JSONB): Array of exercise details `{name, sets, reps}`.

### `member_workouts`
Assignments of workouts to specific members.
- `member_id` (FK).
- `workout_id` (FK).

### `diet_plans`
Nutrition templates.
- `name` (Text).
- `target_calories` (Integer).
- `meals` (JSONB): Array of meal details.

## 5. Security Model (Row Level Security)

This is the most "study-worthy" part of the system.

**Example Policy: Tenant Isolation**
```sql
CREATE POLICY "Users can only see their own tenant data" ON public.members
FOR ALL USING (
    tenant_id = (SELECT tenant_id FROM users_profile WHERE id = auth.uid())
);
```
*Translation:* "Allow a user to access a row in the `members` table ONLY IF the `tenant_id` on that row matches the `tenant_id` on the user's profile."

**Example Policy: Super Admin Access**
Some tables (like `saas_plans`) are readable by everyone but writable only by Super Admins.
```sql
CREATE POLICY "Super Admin Full Access" ON saas_plans
FOR ALL USING (
    (SELECT role FROM users_profile WHERE id = auth.uid()) = 'super_admin'
);
```

## Useful SQL Snippets

### Check your current user role & tenant
```sql
SELECT * FROM users_profile WHERE id = auth.uid();
```

### Manually Update a Tenant's Features (Emergency)
```sql
UPDATE tenants 
SET features = '["members", "billing", "workouts", "diet-plans"]'::jsonb 
WHERE id = 'target-tenant-uuid';
```
